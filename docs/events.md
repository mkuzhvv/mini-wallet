# Kafka и outbox

## Участники и топик

Ledger публикует проведённые операции; statement строит по ним проекцию выписки. Payment получает результат синхронно по REST и события не потребляет.

- Топик: `ledger-transactions`.
- Ключ сообщения: `transactionId`.
- Consumer group: `statement-service`.
- В Compose топик создаётся автоматически: 3 партиции, replication factor 1.

## Формат сообщения

В Kafka отправляется JSON из `TransactionPostedEvent` без дополнительного конверта:

```json
{
  "transactionId": "11111111-1111-4111-8111-111111111111",
  "type": "TRANSFER",
  "amount": 25.00,
  "currency": "RUB",
  "sourceWalletId": "22222222-2222-4222-8222-222222222222",
  "sourceUserId": "44444444-4444-4444-8444-444444444444",
  "targetWalletId": "33333333-3333-4333-8333-333333333333",
  "targetUserId": "55555555-5555-4555-8555-555555555555",
  "createdAt": "2026-11-01T10:00:00Z"
}
```

`type` — DEPOSIT или TRANSFER. Для пополнения источником выступает SYSTEM, поэтому `sourceUserId` равен `SYSTEM`.

`TRANSACTION_POSTED` хранится в колонке `event_type` таблицы outbox. В само Kafka-сообщение входят только поля JSON выше. Отдельного сообщения об отклонённом платеже нет: отклонённая денежная операция откатывается.

## Публикация

1. Ledger в одной транзакции сохраняет балансы, операцию, проводки и outbox.
2. `OutboxPublisher` с задержкой 1 секунду между проходами читает строки с `sent_at IS NULL`.
3. Publisher отправляет payload в Kafka и ожидает подтверждение.
4. После отправки выставляет `sent_at`; отметка сохраняется в транзакции publisher.
5. При ошибке публикации проход завершается, неотправленные строки остаются для следующей попытки.

Если сообщение доставлено, а отметка outbox не сохранилась, оно будет отправлено повторно. Это схема at-least-once: потребитель должен учитывать дубли. Kafka и PostgreSQL не участвуют в общей распределённой транзакции.

## Обработка выписки

Consumer десериализует сообщение и проверяет наличие записей по `transactionId`. Затем в одной транзакции создаёт две строки:

- OUT — источник, его владелец и кошелёк получателя;
- IN — получатель, его владелец и кошелёк источника.

Для SYSTEM тоже создаётся строка. API ограничивает выдачу владельцем из JWT. Дополнительная защита от дублей — уникальная пара `(transaction_id, wallet_id)`.

Время записи берётся из `createdAt` события. Глобальный порядок доставки не используется для сортировки выписки: API возвращает записи по времени операции. Проекция может отставать от баланса.

## Ошибки и границы реализации

- Неразбираемый JSON логируется и пропускается.
- Старое сообщение без `sourceUserId` / `targetUserId` логируется и пропускается.
- Остальные исключения передаются стандартному обработчику Spring Kafka; отдельные retry/DLQ-механизмы в проекте не настроены.
- Outbox использует polling; очистка отправленных строк и координация нескольких publisher-инстансов не реализованы.
- В сообщении нет `schemaVersion`, `correlationId` или описания платежа.
